On starting a slow site

2026.08.13

Most personal sites get built the week before they're needed and abandoned the week after. This one is meant to work differently: a place to put down a thought before it evaporates, not a portfolio performing busyness for whoever's reading.

The rule for this page, going forward, is simple — nothing goes here unless it would survive being read a year from now. Not because everything has to be profound, but because most writing that's just performance doesn't survive that test, and it's an easy filter to keep.

Why static, why plain HTML

No build step, no framework to keep updated, no dependency that quietly breaks in eighteen months. A new post is a copy of this file, a new line in posts.json, and a git push. That's the whole workflow — see the README in the repo root for the exact steps.

The maintenance cost of a personal site should round to zero, or it stops being personal.
